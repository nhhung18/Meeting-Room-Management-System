# Task #10: Room CRUD + Equipment + Soft Delete + Status

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement full Room CRUD in room-service with JSONB equipment, three-state status, soft delete, Alembic migration, and unit + integration tests.

**Architecture:** Layered — API router → Service → Repository → SQLAlchemy ORM → PostgreSQL (room_db). Sync SQLAlchemy. FastAPI dependency injection for DB sessions. This creates the project's FIRST proper ORM model (booking-service used raw SQL migrations with `target_metadata=None`).

**Tech Stack:** Python 3.12, FastAPI, SQLAlchemy 2.x (sync, mapped_column), Alembic, PostgreSQL JSONB, Pydantic v2, pytest

**Spec:** `docs/erd.md` (rooms table §4), `docs/assumptions.md` (assumptions #2, #3), `docs/adr/0003-room-data-access-via-events.md`

## Global Constraints

- Python 3.12, ruff lint, line length 100
- Sync SQLAlchemy only (no async) — project decision in CLAUDE.md
- All timestamps UTC `TIMESTAMP WITH TIME ZONE`, soft delete via `deleted_at`
- Equipment: JSONB array of strings on rooms table (NOT separate table — ERD §4)
- Status: VARCHAR(50) CHECK IN ('AVAILABLE', 'MAINTENANCE', 'ARCHIVED')
- Event publishing (RabbitMQ) is OUT OF SCOPE — that's a later task
- Auth/RBAC is OUT OF SCOPE — that's task #12
- Conventional commits, branch `feat/room-crud`

## Review Focus

1. **Partial unique on name:** two active rooms must not share a name, but a soft-deleted name is reusable — integration test `test_duplicate_name_allowed_when_one_is_deleted` pins this
2. **PATCH with no fields sent:** `model_dump(exclude_unset=True)` returns `{}`, update should be a no-op (not crash) — unit test in service
3. **Capacity zero/negative at DB level:** Pydantic rejects it, but the CHECK constraint is defense-in-depth — integration test `test_capacity_must_be_positive`
4. **List with status filter + soft delete:** query must AND both conditions, not leak deleted rooms — service unit test
5. **`updated_at` on soft delete:** must update alongside `deleted_at` — repo sets both explicitly
